## Задание 1. СУБД

### Кейс

Крупная строительная компания, которая также занимается проектированием и девелопментом, решила создать
правильную архитектуру для работы с данными. Ниже представлены задачи, которые необходимо решить для
каждой предметной области.

Какие типы СУБД, на ваш взгляд, лучше всего подойдут для решения этих задач и почему?

### Условие

1.1. Бюджетирование проектов с дальнейшим формированием финансовых аналитических отчётов и прогнозирования рисков.
СУБД должна гарантировать целостность и чёткую структуру данных.

### Ход решения

Для формирования аналитических отчётов и прогнозирования рисков я бы выбрал реляционную СУБД. Реляционная БД хранит данные в таблицах, позволяет связывать их между собой. Также реляционные БД поддерживают транзакции, одним из свойств которых является согласованность, то есть поддержание целостности данных.

### Условие

1.1.* Хеширование стало занимать длительно время, какое API можно использовать для ускорения работы?

### Ход решения

Если вопрос касается кеширования и ускарения работы, то можно использовать вспомогателью БД Redis.

Redis - БД, которая хранит данные в оперативной памяти и обеспечивает быстрый доступ к информации. Redis зачастую используют как вспомогательную базу данных вместе с основной.

Приложение сначала обращается к Redis и проверяет наличие информации. Если данные есть в кэше, ответ возвращается сразу из Redis, не обращаясь к основной базе данных. Если данных нет, приложение обращается к основной БД и сохраняет полученную информацию для последующих ответов через Redis.

Таким образом снижается нагрузка на БД и ускоряется ее работа.

### Условие

1.2. Под каждый девелоперский проект создаётся отдельный лендинг, и все данные по лидам стекаются в CRM к
маркетологам и менеджерам по продажам. Какой тип СУБД лучше использовать для лендингов и для CRM?
СУБД должны быть гибкими и быстрыми.

### Ход решения

Если данные нужно вносить и изменять гибко и быстро, то я бы выбрал документо-ориентированную БД, так как она может хранить данные о клиентах, продажах в JSON документах. Изменения вносятся проще, потому что БД не требует жёсткой схемы и структуры, что позволяет гибко добавлять новые поля.

### Условие

1.2.* Можно ли эту задачу закрыть одной СУБД? И если да, то какой именно СУБД и какой реализацией?

### Ход решения

Да, задачу можно закрыть одной СУБД, например MongoDB.

Данные с лендингов и из CRM системы могут быть по разному структурированы, а MongoDB позволяет хранить эти данные в виде документов и гибко добавлять новые поля без определенной схемы, разделив данные по коллекциям.

### Условие

1.3. Отдел контроля качества решил создать базу по корпоративным нормам и правилам, обучающему материалу
и так далее, сформированную согласно структуре компании. СУБД должна иметь простую и понятную структуру.

Исходя из этой логике я бы выбрал иерархаческую БД, т.к. она полностью удовлетворяет данным требованиям и структурировано содержит в себе документы в формате родитель - потомок.

### Условие

реализовать?

### Ход решения

Да, под эту задачу можно использовать вышеуказанную БД MongoDB.
Реализовать данную задачу можно путём разделения документов по коллекциям.

### Условие

1.4. Департамент логистики нуждается в решении задач по быстрому формированию маршрутов доставки материалов
по объектам и распределению курьеров по маршрутам с доставкой документов. СУБД должна уметь быстро работать

## Задание 3. SQL vs NoSQL

### Условие

3.1. Напишите пять преимуществ SQL-систем по отношению к NoSQL.

### Ход решения

1. SQL-базы данных имеют строгую схему данных. В них заранее определяются таблицы, типы данных и связи между ними, они лучше подходят для хранения структурированной информации.
2. В SQL-базах данных информация хранится в таблицах, которые можно связывать между собой и создает зависимость между ними.
3. SQL-базы данных имеет мощный язык запросов. С его помощью можно выполнять фильтрацию, сортировку, группировку и объединение данных из разных таблиц.
4. SQL-базы данных лучше подходят для задач, где важна целостность данных, т.к. используют транзакционную модель и поддерживают ACID-свойства.
5. SQL-системы имеют развитые механизмы индексирования. Это помогает быстрее выполнять сложные запросы.

### Условие

3.1.* Какие, на ваш взгляд, преимущества у NewSQL систем перед SQL и NoSQL.

### Ход решения

NewSQL лучше тем, что объединяет преимущества SQL и NoSQL.

От SQL он сохраняет привычные SQL-запросы, реляционную модель и транзакции с ACID. От NoSQL берёт горизонтальное масштабирование, распределение нагрузки между узлами и высокую производительность.

Поэтому NewSQL подходит для задач, где одновременно нужны целостность данных, транзакции и возможность работать с большой нагрузкой.

## Задание 4. Кластеры

### Условие

Необходимо производить большое количество вычислений при работе с огромным количеством данных, под эту задачу
выделено 1000 машин.

На основе какого критерия будете выбирать тип СУБД и какая модель *распределённых вычислений*
здесь справится лучше всего и почему?

### Ход решения

Для данной задачи я бы выбрал модель распределённых вычислений MapReduce.

MapReduce — это модель распределённых вычислений, которая используется для параллельной обработки очень больших наборов данных в компьютерных кластерах. Суть этой модели заключается в том, что большой массив данных делится на части, каждая часть обрабатывается параллельно на отдельном узле, а затем все результаты объединяются.

Работа MapReduce состоит из трёх этапов: Map, Shuffle и Reduce. На этапе Map данные обрабатываются, на этапе Shuffle перераспределяются по ключам, а на этапе Reduce результаты объединяются в итоговый результат.

Таким образом, MapReduce позволяет распределить вычисления между большим количеством машин и эффективно обрабатывать большие объёмы данных.
