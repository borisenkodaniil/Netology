## Задание 1

### Условие

Опишите основные преимущества использования масштабирования методами:

- активный master-сервер и пассивный репликационный slave-сервер;
- master-сервер и несколько slave-серверов.

*Дайте ответ в свободной форме.*

### Ход решения

### Активный master и пассивный slave

`Master` — основной сервер, на котором выполняется запись данных.  
`Slave` получает изменения с master и хранит копию данных.

Преимущества:

- повышается отказоустойчивость;
- есть дополнительная копия данных;
- при проблемах с master можно использовать slave для восстановления работы;
- часть тяжёлых запросов можно выполнять на slave, чтобы меньше нагружать master.

### Master и несколько slave

В этой схеме запись также выполняется на `master`, но серверов `slave` несколько.

Запросы на чтение можно распределять между slave-серверами.

Преимущества:

- распределение нагрузки на чтение;
- снижение нагрузки на master;
- повышение отказоустойчивости;
- возможность добавлять новые slave при увеличении нагрузки.

**Вывод:** один slave повышает отказоустойчивость, а несколько slave позволяют распределять нагрузку на чтение.

## Задание 2

*Примечание:* Задание выполнено ранее в [11.06 Репликация и масштабирование. Часть 1](../11.06%20Репликация%20и%20масштабирование.%20Часть%201/README.md).

### Условие

Разработайте план для выполнения горизонтального и вертикального шаринга базы данных. База данных состоит из трёх таблиц:

- пользователи;
- книги;
- магазины (столбцы произвольно).

Опишите принципы построения системы и их разграничение или разбивку между базами данных.

*Пришлите блоксхему, где и что будет располагаться. Опишите, в каких режимах будут работать сервера.*

### Ход решения

В базе данных есть три таблицы:

- `users` — пользователи;
- `books` — книги;
- `stores` — магазины.

### Вертикальный шардинг

При вертикальном шардинге разные части данных размещаются на разных серверах.

Для данной базы можно разделить данные следующим образом:

| Данные | Сервер |
|---|---|
| `users` | `db_users` |
| `books` | `db_books` |
| `stores` | `db_stores` |

Преимущества:

- нагрузка распределяется между серверами;
- разные части системы можно масштабировать отдельно;
- уменьшается нагрузка на один общий сервер.

### Горизонтальный шардинг

При горизонтальном шардинге одна таблица разделяется по строкам между несколькими серверами.

Например, таблицу `users` можно разделить по `id`:

| Условие | Сервер |
|---|---|
| `id <= 500000` | `users_shard_1` |
| `id > 500000` | `users_shard_2` |

Приложение определяет, на какой сервер отправить запрос, по значению `id`.

Например:

```text
user_id = 100    → users_shard_1
user_id = 700000 → users_shard_2
```

**Вывод:**

- вертикальный шардинг — разные таблицы или части системы располагаются на разных серверах;
- горизонтальный шардинг — строки одной таблицы распределяются между несколькими серверами.
