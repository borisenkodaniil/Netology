## Задание 1. Резервное копирование

### Условие

Финансовая компания решила увеличить надёжность работы баз данных и их резервного копирования.

Необходимо описать, какие варианты резервного копирования подходят в случаях:

1.1. Необходимо восстанавливать данные в полном объёме за предыдущий день.

1.2. Необходимо восстанавливать данные за час до предполагаемой поломки.

1.3.* Возможен ли кейс, когда при поломке базы происходило моментальное переключение на работающую или починенную базу данных.

*Приведите ответ в свободной форме.*

### Ход решения

### 1.1. Восстановление данных в полном объёме за предыдущий день

Для этого подойдёт **полное резервное копирование**.

Допустим, раз в сутки создаётся полная копия базы данных. При поломке можно восстановить базу из копии за предыдущий день.

Преимущества:

- простое восстановление;
- все данные находятся в одной резервной копии.

Недостатки:

- требуется больше места;
- создание копии занимает больше времени.

### 1.2. Восстановление данных за час до предполагаемой поломки

Для этого подойдёт **инкрементный бэкап**.

Инкрементальная копия содержит только изменения  резервного копирования с момента последнего резервного задания.

Такой способ позволяет создавать точки восстановления данных каждый час и значительно экономит место по сравнению с **полным резервным копированием**

### 1.3.* Переключение при поломке

Да, это возможно с помощью **репликации**.

При отказе основного сервера одна из реплик может принять его роль и стать основным сервером.

Это позволяет значительно уменьшить время простоя системы.

## Задание 2. PostgreSQL

### Условие

2.1. С помощью официальной документации приведите пример команды резервирования данных и восстановления БД (`pg_dump`/`pg_restore`).

2.1.* Возможно ли автоматизировать этот процесс? Если да, то как?

*Приведите ответ в свободной форме.*

### Ход решения

### 2.1. Резервное копирование

Для создания резервной копии PostgreSQL можно использовать `pg_dump`.

Пример:

```bash
pg_dump -Fc postgres > db.copy
```

Где:

- `postgres` — имя базы данных;
- `-Fc` — создание резервной копии в формате `custom`;
- `db.copy` — файл резервной копии.

Для восстановления базы используется `pg_restore`:

```bash
pg_restore -d postgres_new db.copy
```

Где:

- `postgres_new` — база данных, в которую выполняется восстановление;
- `db.copy` — файл резервной копии.

### 2.1.* Автоматизация

Да, резервное копирование можно автоматизировать, используя `cron`.

К примеру, запуск РК БД требуется каждый день в `00:00`:

```cron
0 0 * * * pg_dump -Fc postgres > /backup/db.copy
```

Таким образом, `pg_dump` будет автоматически запускаться по заданному расписанию.

## Задание 3. MySQL

### Условие

3.1. С помощью официальной документации приведите пример команды инкрементного резервного копирования базы данных MySQL.

3.1.* В каких случаях использование реплики будет давать преимущество по сравнению с обычным резервным копированием?

*Приведите ответ в свободной форме.*

### Ход решения

### 3.1. Инкрементное резервное копирование

Для создания инкрементных резервных копий можно использовать **MySQL Enterprise Backup**.

Пример:

```bash
mysqlbackup --defaults-file=/home/dbadmin/my.cnf \
  --incremental \
  --incremental-base=history:last_backup \
  --backup-dir=/home/dbadmin/temp_dir \
  --backup-image=incremental_image1.bi \
  backup-to-image
```

- `--incremental` — создаёт инкрементальную резервную копию;
- `--incremental-base=history:last_backup` — использует последнюю успешную резервную копию как основу;
- `--backup-image` — задаёт имя файла резервной копии.

### 3.1.* Реплика и обычный бэкап

Если основной сервер выйдет из строя, реплика может быстрее принять его роль, чем ожидать восстановление БД из резервной копии.

Также реплика может использоваться для:

- уменьшения времени простоя;
- снижения возможной потери последних данных;
- выполнения тяжёлых запросов без нагрузки на основной сервер;
- выполнения резервного копирования с реплики.
